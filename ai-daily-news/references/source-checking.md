# 来源核验与素材规则

在采集脚本生成候选后读取本文件。候选源负责发现，一手来源负责证明。

服务端运行时同时读取 `server-runtime.md`。使用普通 HTTP 优先、内置 `control-in-app-browser` skill 兜底（处理 JS 页面和截图），不依赖桌面浏览器或登录态。

## 来源优先级

1. 一手来源：官方博客、产品文档、更新日志、GitHub 仓库/Release/Issue、论文、模型卡、公司公告、官方社交账号原文。
2. 强二手来源：可信科技媒体、会议与标准组织、包注册表、应用商店页面。
3. 线索来源：Google News 聚合页、HN、社区评论、视频平台、同类早报和普通媒体转载。

官方 RSS 中的条目可以直接作为待核验的一手候选，但仍要打开原页面确认正文。Google News、HN、媒体 RSS、HF 趋势分数、GitHub stars 只说明“值得看”，不证明新闻核心事实。

## 核验流程

对每条候选执行：

1. 提取实体、产品、项目、模型、论文、版本、日期和动作词。
2. 先打开候选 URL；如果是官方页面，确认页面确实包含标题中的核心动作。
3. 如果只有标题、摘要或聚合链接，按顺序检索：
   - `<实体> <产品/模型/项目> official`
   - `<实体> <产品/模型/项目> release`
   - `<实体> <产品/模型/项目> blog`
   - `<实体> <产品/模型/项目> GitHub`
   - `<实体> <产品/模型/项目> arxiv`
   - `site:<可能的官方域名> <产品/模型/项目>`
4. 国际实体同时搜索英文；中国实体同时搜索中文。
5. 记录支持核心事实的原句、参数、发布日期和 URL。不要把别的文章补充的上下文混成官方事实。
6. 至少一个来源确认核心事实后再写完整稿；找不到时进入"需核实选题池"。

### 状态变更核验（重要）

同一事件可能经历多个阶段，每个阶段的日期和事实不同。必须区分：

| 阶段 | 示例 |
|------|------|
| 宣布/预告 | "将于 X 日开源" — 此时尚未实际开放 |
| 正式发布/上线 | 权重已上传、API 已可用、代码已推送 |
| 后续适配/生态 | 第三方宣布 Day-0 支持、社区集成 |

**核心规则**：写稿时以**最新已确认状态**为准，而非最初的公告日期。例如模型在 7/31 宣布开源，但权重在 8/3 才实际上传到 HuggingFace，应写为"8/3 开源"而非"7/31 开源"。

检查方法：
- 打开官方页面（HuggingFace 模型页、GitHub Release、产品页）确认内容是否已实际存在，而非预告。
- 对比公告日期和页面最后更新日期。
- 如果标题写"即将"但实际页面已有内容，说明状态已变更，需要更新表述。

常见官方域名定向搜索：

- OpenAI：`site:openai.com`、`site:platform.openai.com`
- Anthropic：`site:anthropic.com`
- Google：`site:blog.google`、`site:deepmind.google`
- NVIDIA：`site:nvidia.com`
- GitHub：`site:github.blog`、`site:github.com`
- Hugging Face：`site:huggingface.co`
- 论文：`site:arxiv.org`

## 可信度

- `高`：一手来源明确确认核心事实。
- `中`：可信二手来源确认，但一手来源缺失或信息不完整。
- `低`：只有社区、聚合页或普通转载；不要生成确定口吻的完整稿。
- `需核实`：没有来源确认，或来源与候选标题冲突；只放选题池。

分数、跨源次数、点赞、stars、下载量和趋势值不得直接提升事实可信度。

## 日更入选门槛

- 采集脚本输出全部候选 `candidates[]`，不再有预设的短名单。AI 分析师自行阅读全部候选并决定核验哪些。
- 最终目标 8 条，允许 7–10 条；每条至少有一个能确认核心事实的来源。
- 优先保留官方发布、跨源重复、明确模型/产品/仓库/论文实体的事件。
- Google News、HN 和媒体单独出现的标题必须找到一手来源，否则不进入最终日报。
- ETF、融资融券、股价目标、买卖评级、低热度仓库和泛泛评论不占最终名额。
- 同一事件的不同媒体标题只保留一条，相关链接可以合并到该条目。
- 24 小时内不足 7 条时扩大到 48 小时；仍不足时少发，不降低核验标准。

## 图片与截图

打开每个已核验来源，列出具体可用区块：

```text
页面：
可截图区块：
- 区块名称：
  素材类型：首屏 / 产品截图 / 架构图 / Demo / benchmark / 模型卡 / 论文图
  截图内容：
  适合用途：
  版权备注：
```

优先使用：

- 官方产品截图、发布页图片、文档图示和更新日志界面。
- GitHub README 图表、Release assets、项目页 Demo。
- 模型卡、benchmark 表、论文架构图和实验结果图。

禁止使用：

- 视频平台截图、封面、章节关键帧和创作者总结卡片（如 YouTube 视频缩略图）。
- 媒体配图、聚合页缩略图或其他早报截图替代官方素材。
- 付费墙图片、来源不明图片或声称未经确认的授权。

截图时用 `control-in-app-browser` skill 打开页面，关闭 Cookie 弹窗和遮罩，滚动触发懒加载。优先截具体区块，不截不可读的长页面。截图后用 `images_understand` 检查是否空白、被遮挡或裁切错误；不合格时换 clip 区域重截，直到拿到合格图。

每张图片建议必须包含 `url`、`source_page`、`section_name`、`what_to_capture` 和 `rights_note`。

## 写作边界

- 只写来源明确出现的事实、参数、价格、日期、榜单和用户数据。
- 把“最佳、首个、最强”等宣传词改写为来源支持的窄表述，并说明是官方或 benchmark 声明。
- 默认使用客观新闻简报口吻；用户明确要求时才启用 KOC、第一人称或轻测评。
- 标题不超过 20 字，保留主体、产品/模型名和动作；参数、价格和发布日期放正文。
- 正文不得把候选发现渠道写成证据，不出现“Google News 显示”“HN 上说”“UP 主称”等表述。
- 不洗写公众号、媒体稿、UP 主文字版或其他早报；它们只用于定位一手 URL。
- 每篇末尾给出实际打开并核验过的相关链接。
